# ゆるコーデ

## 1. サービス概要

ゆるコーデは、毎朝の服選びにかかる時間とストレスを最小限にするためのWebアプリです。

ファッションを楽しむためのアプリではなく、「今日何を着よう」という**意思決定の疲労を減らす生活支援ツール**として、手持ちの服から最適なコーディネートを一瞬で提案します。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

私自身、長年毎朝の服装に悩まされてきました。クローゼットの前に立って、どの色とどのアイテムを組み合わせればいいか分からず、気づけば30分以上経っていることがよくあります。

選択肢が多いとかえって決められなくなり、最終的に「昨日と同じでいいや」となってしまう。そんな自分に嫌気がさすこともありました。

また、既存のファッションアプリを使ってみたものの、**洋服の登録があまりにも面倒**で、3着登録したところで挫折しました。写真を撮って、色を選んで、カテゴリを選んで……「服選びを楽にしたいだけなのに、なんでこんなに手間がかかるのだろう」という違和感が残りました。

### 2-2. なぜそれが「気になった」のか

私はもともと決断力が弱く、何を決めるにも時間がかかるタイプです。服装だけでなく、昼ご飯を決めるのも、仕事の優先順位をつけるのも苦手です。

「毎朝30分も服選びに時間を使うのは、人生の無駄だ」と。もっと大切なことに時間と精神力を使いたい、という思いがずっとありました。

ファッションセンスを磨きたいわけではない。ただ、**何も考えずに「これを着れば大丈夫」と思える状態**になりたい。その思いがこのアプリの出発点です。

---

## 3. 課題の整理

### 3-1. 表に見えている困りごと

- 毎朝何を着るか決めるのに時間がかかる
- 選択肢が多すぎて決められない
- 結局いつも同じ組み合わせになってしまう
- 既存アプリは洋服の登録が面倒で続かない

### 3-2. 本当に解決したい課題は何か

- なぜ毎朝服選びに時間がかかるのか？ → 選択肢が多すぎて決められないから
- なぜ選択肢が多いと決められないのか？ → 自分に何が合うか分からないから
- なぜ既存アプリを使わないのか？ → 登録が面倒で、始める前に挫折するから

→ 本当に解決したい課題：**「登録の手間」と「選択の疲労」の両方を極限まで減らし、何も考えずに最適な服を着られる状態をつくること**

---

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

- **年齢**：25〜35歳
- **職業**：毎朝限られた時間で出勤準備をする会社員
- **生活・状況**：一人暮らしで、平日の朝の準備時間は30分程度。残業も多く、服選びにかける時間と気力がない
- **特徴**：ファッションに強いこだわりはないが、場に合わない服を着て恥をかきたくもない。「無難で自分に合った服」を最小限の労力で選びたい

### 4-2. 自分とユーザーの距離

**自分自身**です。私自身がまさにこの課題を抱えていて、同じ悩みを持つ人に届けたいと思っています。

### 4-3. 実際に使われる可能性について

- **最初に使いそうな人**：私の周りの友達（同じように朝の服装で悩んでいる人）
- **思い出す場面**：朝起きてクローゼットの前で「今日何着よう……」と固まったとき
- **代わりに使っているもの**：SNSでコーデを検索する、昨日と同じ服を着る、適当に引っ張り出す
- **置き換えてまで使う理由**：SNSは情報が多すぎて探すのが大変。このアプリは手持ちの服から一瞬で提案してくれるので、探す手間も選ぶ疲労もゼロ

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ

- **きっかけ**：朝の服選びで毎日ストレスを感じているときに、このアプリを知る
- **最初の一歩**：カテゴリと色を選択式で登録するだけ（選択肢にない場合はテキスト入力も可能、任意でメモ欄もある）。5着だけ登録すれば、1着30秒、合計3分程度で使い始められる
- **続ける理由**：ワンタップでコーデが決まる体験を一度知ると、もう自分で悩む気になれない。天気やシチュエーションに合った服を自動で提案してくれる

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

**サービス1：XZ（クローゼット）**

- **URL**：https://xz-app.jp/
- **できること**：手持ち服の写真登録、天気・気温に連動した1週間分のコーデ提案、カレンダー機能、テンプレートを活用したコーデ作成機能
- **本アプリとの違い**：天気連動機能はあるが、「通勤」「デート」などのシチュエーション別の提案はない。また、洋服登録は写真撮影やカメラロールから選ぶするが前提で、テキスト入力などができる簡易登録がない

**サービス2：WEAR**

- **URL**：https://wear.jp/
- **できること**：モデルや一般ユーザーのコーデ写真の閲覧・検索、ファッションジャンル診断、ZOZOTOWNと連携したアイテム購入。
- **本アプリとの違い**：WEARのコアは「モデルのコーデを参考にして新しいファッションを見つけ、気に入ったアイテムを購入する」ことである。お持ちのアイテムで手持ち服を登録することはできるが、登録した服からコーデを自動提案することはなく、表示されるのはモデルのコーデが中心である。また、登録時は写真撮影・カテゴリ・色・ブランドがすべて必須で手間がかかる。「ファッションを楽しむ・買う」ためのSNSであり、毎朝の服選びを代行するものではない

**サービス3：StyleHint（スタイルヒント）**

- **URL**：https://www.stylehint.com/
- **できること**：UNIQLO・GU公式の着こなし発見アプリ。手持ち服を撮影すると画像認識で類似のUNIQLO・GU商品を検索し、そのアイテムを使ったモデルのコーディネート（ボトムス・小物など）を表示する。表示されたアイテムはそのままオンラインストアで購入できる
- **本アプリとの違い**：StyleHintは手持ち服を撮影すると、その服に似たアイテムを使ったモデルのコーディネートを表示する。表示された類似アイテム自体は参考として閲覧できるが、コーデを構成する他のアイテム（ボトムス・小物など）はすべてUNIQLO・GUの商品であり、購入リンクが付いている。つまり「手持ち服を起点に新しい買い足しを提案する」設計であり、登録済みの手持ち服だけで組み合わせを完結させることはしない。また、手持ち服を手動で登録する場合は写真撮影（またはアルバムから選択）が必須のほか、ブランド名・カテゴリ・色をすべて手動で選択する必要があり、登録項目が多い。また、UNIQLO・GUなどの公式ブランド以外の服は自動認識の対象外である

### 5-2. それでも自分が作りたい理由

XZ・WEAR・StyleHintの3つを調査・比較して、自分が作りたいアプリの立ち位置が明確になりました。

XZを実際に使ってみて、2つの大きな不満がありました。

**1つ目は、登録が圧倒的に面倒なこと。** 写真を撮って、色を選んで、カテゴリを選んで……という作業が1着ごとに発生し、10着登録する前に疲れてアプリを閉じました。「服選びを楽にしたい」という目的のために、なぜこんなにも手間をかけなければならないのか、本末転倒だと感じました。

**2つ目は、機能が多すぎて迷うこと。** クローゼット診断、1週間コーデ作成、カレンダー、テンプレート……さまざまな機能があるが、「今日何を着ればいいか」だけを知りたい私にとって、どの機能を使えばいいか分からず、かえって迷ってしまいました。

WEARは、そもそも手持ち服からコーデを提案するアプリではありません。モデルのコーデを参考にしたり、AIがファッションジャンルを診断したり、気に入ったアイテムをZOZOTOWNで購入したりと、「おしゃれになりたい」「ファッションを楽しみたい」人向けのSNSです。クローゼット機能で手持ち服を登録することはできますが、登録した服からコーデを自動で提案することはなく、あくまでモデルのコーデ発見と購入促進が中心です。登録も写真・カテゴリ・色・ブランドがすべて必須で手間がかかります。

StyleHintは、手持ち服を撮影するという一見似た機能を持ち、手持ち服に似たアイテムやそれを使ったコーデを参考として提示します。しかし、コーデを構成する他のアイテムはすべてUNIQLO・GUの商品で購入リンクが付いており、「手持ち服に合う新しいアイテムを買い足す」ことを前提としています。登録済みの手持ち服だけでトップス・ボトムス・アウターを組み合わせて、追加購入なしにコーデを完結させることはしません。手動で服を登録する場合も写真撮影が必須で、ブランド名・カテゴリ・色をすべて手動選択する必要があり、登録の手間は小さくありません。

つまり、**「手持ち服の登録が面倒」という課題は、クローゼット管理アプリのXZ、ファッションSNSのWEAR、ブランド公式アプリのStyleHintのすべてに共通しており、写真撮影を前提としない選択式＋テキスト入力による簡易登録はどのアプリも行っていません**。また、「登録した手持ち服だけで組み合わせを自動提案する」アプリも「毎朝の服選びを代行する」という目的に特化したアプリも存在しません。

XZはクローゼット管理アプリ、WEARはファッションSNS、StyleHintはブランド公式の購入促進アプリであり、3つとも「ファッションを楽しむ・新しく買う」人向けに作られています。私が欲しいのは「ファッションを楽しむアプリ」ではなく、**「服選びという家事を代わりにやってくれるアプリ」**なのです。

### 5-3. 差別化ポイント

**このアプリは、【服選びに時間も気力も使いたくない人】の【「何も考えずに最適な一着を選びたい」という願い】を一番叶えるアプリです。**

既存アプリとの違いは、**「登録の手間を極限まで減らす」**ことを最優先に設計している点です。

| 比較項目 | 既存アプリ（XZなど） | ゆるコーデ |
|---------|-------------------|-----------|
| 洋服登録 | 写真撮影＋色選択＋カテゴリ選択（1着1〜2分） | カテゴリ・色の選択式＋テキスト入力＋任意メモ（1着30秒） |
| 提案の軸 | 天気・気温を中心に提案 | 天気に加え、シチュエーション（通勤・デートなど）も考慮して提案 |
| 機能コンセプト | クローゼット管理・コーデ作成を楽しむ多機能アプリ | 「服選び」という行為そのものを代行する生活支援ツール |
| 根本コンセプト | ファッションを楽しむツール | 意思決定疲労を減らすツール |

差別化の核となる3つの体験：

1. **3分で使い始められる**：カテゴリと色を選ぶだけの選択式登録（テキスト入力にも対応）で5着登録すれば、すぐに提案が受けられる。写真撮影も複雑な設定も不要
2. **シチュエーションに合った提案**：天気だけでなく「通勤」「デート」などの場面を選ぶことで、気温にも場にも合ったコーデを提示。既存アプリにはない組み合わせ
3. **MVPは「今日着る服を決める」ことだけに集中**：SNS的要素・EC購入・ファッション診断など、「毎朝の服選びを代行する」という目的から逸れる機能はMVPではあえて持たない。着用履歴や嗜好学習などの機能は本リリース以降に段階的に追加し、まずは「ただ今日着る服を知りたい」だけのユーザーに迷いのない体験を提供する

### 6-1. ユーザーの変化

- **行動の変化**：毎日の服選びの時間が30分から30秒に短縮
- **気持ちの変化**：「何着よう……」というモヤモヤから解放される

「このサービスは、**服選びに時間も気力も使いたくない人**が、**何も考えずに最適なコーデを身につけて一日を始められる**ようになるサービスです。」

## 7. このアプリで実現すること

### MVPで作る機能（4つ）

**1. 選択式＋テキスト入力による洋服登録**

写真撮影や複雑な設定は不要。基本はカテゴリ（トップス/ボトムス/アウターなど）と色を選ぶだけで1着30秒で登録完了。選択肢にない色や版型・素材の特徴がある場合は、テキストで直接入力することもできる。これにより、選択式の手軽さを保ちつつ、特殊な洋服でも正確な情報を登録でき、提案の質を担保する。さらに、似たアイテムを識別したい場合に備えて、任意の「呼び名・メモ欄」を1つ設ける（「首元あき」「七分袖」など）。必須項目ではないため登録の手間は増やさず、必要な人だけが入力すればよい。5着あればすぐに提案機能が使える。ユーザーが一番最初につまずく「登録の壁」を徹底的に低くする。

**2. 天気自動連動コーデ提案**

ユーザーが天気を調べて入力する必要はない。GPS位置情報からその日の気温をOpenWeatherMap APIで自動取得し、さらにシステムが現在の年月日から季節（春・夏・秋・冬）を自動で判定する。気温と季節の両方を考慮し、その時期に適した洋服を自動で組み合わせて提案する。ユーザーは余計な情報を入力せず、最適なコーデを受け取れる。

**3. シチュエーション選択機能**

「通勤」「デート」「カジュアル」「フォーマル」など、その日の予定や気分を選ぶだけで、場に合ったコーデに絞り込む。天気とシチュエーションを組み合わせることで、「暑すぎず、場に合った服」をワンタップで提示する。

**4. 明日のコーデを前日に決める機能**

朝の忙しい時間に服を選ぶ必要がないよう、前日の夜にゆっくりコーデを選んで保存できる。天気予報をもとに翌日の気温に合ったコーデを事前に提案し、ユーザーが確定するだけ。翌朝アプリを開くと「今日のコーデ」が表示され、そのまま着るだけ。

### 本リリースで作る機能（6つ）

**5. コーデ評価・嗜好学習**

提案されたコーデに「いいね👍」または「ちがう👎」の2択で評価するだけ。評価データが蓄積されると、ユーザーが好む色や組み合わせの傾向をシステムが学習し、徐々に提案精度が向上する。使えば使うほど「自分専用」のコーデ提案に進化する。

**6. 初回設定アンケート**

登録時に「カジュアル派？きれいめ派？」「好きな色は？」「よく行く場所は？」「体型は？（梨型・リンゴ型・ストレート・ウェーブなど）」の4つの質問に答えるだけで、初期の嗜好プロファイルを作成する。体型の情報を加えることで、体型の長所を活かし短所をカバーするシルエットの提案が可能になり、評価データがゼロの状態でも好みと体型に合った提案を実現する。

**7. 画像認識による洋服自動登録**

写真やカメラロールでの登録だけで、AIが色やカテゴリを自動判定して登録する。選択式の手動登録よりもさらに手間を削減。将来的にはAIモデルの導入も検討する。

**8. 着用履歴カレンダー**

毎日「今日のコーデ」として承認した組み合わせを自動的に記録。カレンダー形式で過去のコーデを振り返ることができる。

**9. 着回し力可視化・着用頻度考慮**

「この服、今月5回着ました」のように各アイテムの着用回数を表示。さらに、着用頻度の低いアイテムを優先的に提案することで、クローゼット全体を満遍なく活用する。

**10. 長期未着用リマインド**

一定期間着ていない洋服を通知で知らせる。「そろそろこの服が活躍する季節です」といった形で提案し、クローゼットの眠っている服を減らす。

## 8. このアプリの懸念点とその対策

### 懸念点①：登録する洋服が少ないと提案の質が下がる

**■ 何が問題になりそうか：**

MVPでは最低5着の登録で提案を開始するが、5着だと組み合わせのパターンが少なく、ユーザーが「提案がショボい」と感じて離脱する可能性がある。

**■ そのために考えている対策：**

登録時に「あと◯着登録すると提案の幅が広がります」といった進捗表示を行い、10着程度までの追加登録を自然に促す。また、5着でも「今日の一着」を確実に提示できる設計にする。

### 懸念点②：提案されたコーデがユーザーの期待に応えられない

**■ 何が問題になりそうか：**

登録されている洋服が少ない場合、ランダム抽選で同じような組み合わせが連続で提案されたり、ユーザーの好みに合わないコーデが出てしまう可能性がある。「またこれ？」「なんか違う」という体験が続くと、ユーザーがアプリを信頼しなくなる恐れがある。

**■ そのために考えている対策：**

MVPでは2つの対策を行う。1つ目は「別のコーデを見る」ボタンを設け、気に入らない場合は再抽選できるようにする。2つ目は、推薦ロジックに「直近3日間に選択したコーデを除外する」フィルターを設け、連続して同じ組み合わせが出ないようにする。また、洋服の登録数が10着未満の場合は「あと◯着登録すると提案のバリエーションが広がります」と表示し、自然に追加登録を促す。

本リリースでは、コーデ評価・嗜好学習機能（本リリース機能5）と初回設定アンケート（本リリース機能6）を組み合わせ、「いいね👍」「ちがう👎」のフィードバックと事前に登録した好みの色・スタイル・体型の情報をもとに、提案精度を段階的に向上させる根本的な解決を図る。

### 懸念点③：画像なし登録では、似たアイテムを識別できない

**■ 何が問題になりそうか：**

MVPの登録はカテゴリと色の選択のみのため、「黒のトップス」を3枚持っているユーザーの場合、提案された1着が具体的にどの服を指すのかが分からない。これは「登録を楽にする」という差別化の裏返しで発生するリスクである。

**■ そのために考えている対策：**

MVPでは、登録時に任意の「呼び名・メモ欄」を1つ設ける。「首元あき」「七分袖」「お気に入り」など、ユーザーが自分で識別できる短い情報を任意で入力できるようにする。必須項目ではないため登録の手間は増やさず、必要な人だけが入力すればよい。提案画面にはカテゴリ・色に加え、メモが入力されている場合はメモを表示し、ユーザーがどの服か一目で分かるようにする。

## 9. 今後の展開・発展の方向性

- **ユーザーはなぜ使い続ける？** → 登録が簡単で、毎朝の服選びがゼロになるから。前日にコーデを決める習慣がつけば、朝のルーティンに欠かせなくなる
- **続けることで何が変わる？** → 毎朝のストレスがなくなり、限られた朝の時間を有効に使える
- **データが溜まると何ができる？** → 評価データによる嗜好学習、着用回数・色の傾向などクローゼット全体の統計が可視化できる
- **今考えている発展案：**
  - コーデ評価による嗜好学習（本リリース機能5）
  - 画像認識で自動登録（本リリース機能7）
  - 着用履歴・着回し力の可視化（本リリース機能8・9）
  - 長期未着用のリマインド（本リリース機能10）
  - 季節の変わり目の衣替え提案

## 10. 技術スタック

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 7.0.3.1
- DB：PostgreSQL
- 使用予定ライブラリ：Devise（認証）、Bootstrap（UI）、ActiveStorage（画像管理）
- 外部API：OpenWeatherMap API（気温・気象データ取得）

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
|------|------------|------|
| Ruby on Rails | 採用 | フルスクラッチで開発するよりRailsはCRUD機能を短時間で実装しやすい |
| Django | 不採用 | Pythonも魅力的だが、Railsのenum・ActiveRecord・RSpecを学習する課題のため。実装思想が異なり、既存Rubyのコード資産が流用できない |
| Spring | 不採用 | 機能が過剰で定型コードが多く開発効率が低下。RSpecのテスト資産が利用不可になる |
| PostgreSQL | 採用 | 多くのPaaSで標準提供されている。JSON型など拡張機能が豊富で、Railsとの相性も良い。将来的なデータ増加にも対応できる |
| SQLite | 不採用 | 開発時は手軽だが、Herokuなどの多くのPaaSではデプロイのたびにファイルシステムがリセットされ、登録した服のデータが消えてしまうリスクがある |
| MySQL | 不採用 | PostgreSQLで十分な機能を満たせる。RailsデフォルトのPostgreSQLの方が設定やトラブルシューティングの情報が多く、開発効率が良い |
| Bootstrap | 採用 | CSSを一から書く手間を省き、短期間で操作性の良い画面を作成可能。複雑なUIを必要としない |
| React | 不採用 | MVPの機能に高度なフロントエンドは不要。学習コストが増え、技術構成が複雑になるため |
| Devise | 採用 | Railsの認証機能でログイン・会員登録を短期間で安全に実装できる |
| ActiveStorage | 採用 | Rails標準の画像管理機能。外部サービス不要で、洋服画像のアップロード・管理を簡単に実装できる |
| OpenWeatherMap API | 採用 | 気温・湿度・天気予報を緯度経度で取得可能。天気連動コーデ提案に必要な気温データを確実に取得できる |
| Yahoo!天気API | 不採用 | 取得できるのは降水強度（mm/h）のみで、気温データが提供されていない。気温に基づくコーデ提案が必須のため不適切 |

### 10-3. 技術的なチャレンジと不安

- **チャレンジしたい点**：Deviseを使った認証機能、OpenWeatherMap APIとの連携
- **不安な点：**
  1. 外部APIとの連携が初めてで、レスポンスの処理やエラーハンドリングに慣れていない
  2. 天気・シチュエーションに基づくコーデ提案ロジックを、シンプルかつ意味のある形で実装できるか
  3. PostgreSQLを使った開発やPaaSへのデプロイ経験がなく、環境構築やデプロイ手順に不安がある
