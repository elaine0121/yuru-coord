# ゆるコーデ

## 1. サービス概要

ゆるコーデは、服選びに悩む人やコーディネートに自信がない人のために、手持ちの服から毎日ぴったりの組み合わせを提案してくれるWebアプリです。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

私自身、長年毎日の服装に悩まされてきました。朝出かけるときに、どの色とどのアイテムを組み合わせればいいか分からなくて、いつも同じような組み合わせになってしまいます。

また、選択障害の傾向があり、選択肢がたくさんあるとどうしても迷ってしまい、最終的には何も決められずに時間だけが過ぎてしまうことがよくあります。

SNSで見かけるおしゃれなコーデを見ると「自分もこんな風にカッコよく決めたいな」と思うのですが、体型の悩みもあり、ただ真似するだけではうまくいきません。体型の欠点を隠しつつ、スタイリッシュに見せるような組み合わせが知りたいと思っています。

### 2-2. なぜそれが「気になった」のか

私はもともと決断力が弱くて、何を決めるのにも時間がかかるタイプです。服装だけでなく、昼ご飯を決めるのも、仕事で優先順位をつけるのも苦手です。

「毎朝30分も服選びに時間を使うのは、もったいないな」と。もっと大切なことに時間を使いたい、という思いがずっとありました。

---

## 3. 課題の整理

### 3-1. 表に見えている困りごと

- 毎朝何を着るか決めるのに時間がかかる
- 同じような組み合わせばかりになってしまう
- 似合う組み合わせが分からない

### 3-2. 本当に解決したい課題は何か

- なぜ毎朝服選びに時間がかかるのか？ → 選択肢が多すぎて決められないから
- なぜ選択肢が多いと決められないのか？ → 自分に似合う組み合わせが分からないから
- なぜ似合う組み合わせが分からないのか？ → 試行錯誤する機会が少ないし、失敗したくないから

→ 本当に解決したい課題：**自分に似合う組み合わせが分からず試行錯誤が続く中で、自分好みのスタイルを自動的に理解・提案してくれるパートナーのような存在があること**

---

## 4. 想定ユーザーについて

### 4-1. 想定しているユーザー

- **年齢**：25〜30代
- **理由**：社会人になると朝の時間が限られるようになり、服装に時間をかけてられない場面が増えるからです
- **生活・状況**：一人暮らしの会社員で、通勤が必要な毎日。平日は残業も多く、朝の準備時間はだいたい30分程度です
- **理由**：朝の限られた時間で服装まで決められず、毎朝ストレスを感じています。アプリで提案してもらえれば、考える時間を大幅に減らせます
- **環境**：通勤電車やオフィスではある程度服装のマナーが求められますが、おしゃれとビジネスのバランスが自分では分かりません
- **理由**：場面（通勤、会議、デートなど）に合わせて提案してもらえるので、マナーを気にせず選べます

### 4-2. 自分とユーザーの距離

**自分自身**です。私自身がまさにこの課題を抱えていて、同じ悩みを持つ人に届けたいと思っています。

### 4-3. 実際に使われる可能性について

- **最初に使いそうな人**：私の周りの友達（同じように朝の服装で悩んでいる人）
- **思い出す場面**：朝起きて「今日何着よう...」と迷ったとき
- **代わりに使っているもの**：今はSNSでコーデを検索したり、同じ服を繰り返し着たりしています
- **置き換えてまで使う理由**：SNSは情報が多すぎて、自分に合うものを探すのが大変です。このアプリは手持ちの服から提案してくれるので、探す手間がゼロです

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ

- **きっかけ**：朝の服装で迷ってストレスを感じているときに、このアプリを知る
- **最初の一歩**：手持ちの服5着だけテキストで登録（5分程度）
- **続ける理由**：使えば使うほど自分の好みを学習してくれて、提案の精度が上がります。朝の準備時間が短くなるのを実感できます

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

- **サービス名**：XZ
- **URL**：XZ(クローゼット)ファッション・洋服 コーディネートアプリ
- **できること**：クローゼット診断機能、天気連動コーデ提案、カレンダー機能、1週間分のコーデ提案、テンプレートを活用したコーデ作成機能

### 5-2. それでも自分が作りたい理由

XZを使ってみたとき、正直「登録が面倒だな」と感じました。写真を撮って、色を選んで、カテゴリを選んで...という作業がすごく手間でした。

また、提案されるコーデが「なんとなく自分じゃない」と思うことが多かったのですが、なぜそう思うかをフィードバックする手段がありませんでした。

「服選びを楽にしたいだけなのに、なんでこんなに手間がかかるのだろう」という違和感がありました。

### 5-3. 差別化を「体験価値」で表現する

**このアプリは、【他のコーデアプリで不満を抱えている人】の【「自分好みのスタイルが見つからない」という悩み】を一番解決するアプリです。**

差別化ポイント：

1. **嗜好学習で「自分専用」に進化する**：提案されたコーデに評価をつけることで、システムがユーザーの好みを理解し、提案精度が上がる。「使えば使うほど自分専用になる」体験を提供
2. **場面（デート、会議など）を選んで提案**：一般的なアプリは天気・気温だけだが、本アプリは外出目的も考慮して提案
3. **テキスト入力で簡単登録**：既存アプリは写真の撮影やアルバムの選択が中心で手間がかかるが、本アプリはテキストでも登録可能

## 6. このサービスで提供したい価値

### 6-1. ユーザーの変化

- **行動の変化**：毎日の服装選びの時間が30分から5分に短縮
- **気持ちの変化**：「何着しよう...」というモヤモヤから解放される
- **考え方の変化**：服装は「悩むもの」から「アプリが自分に合ったものを選んでくれる」に変わる

### 6-2. 価値を一文で表す

「このサービスは**コーデアプリに満足できなかった人**が、**使えば使うほど自分好みのスタイルが見つかる**ようになるサービス」

## 7. このアプリで実現すること

### MVPで作る機能

1. テキスト入力による電子クローゼット機能
2. 天気・シチュエーションを指定したコーデ提案
3. コーデへの評価機能（嗜好学習）

### 本リリースで作る機能

- 画像認識による自動洋服登録
- 音声入力による洋服登録
- 長期間着ていない服の通知
- 体型別のコーデ提案（梨型・リンゴ型など、ユーザーの体型に合ったスタイリングで魅力を最大限に引き出す）

---

## 8. このアプリの懸念点とその対策

**■ 何が問題になりそうか：**

1. ユーザーが洋服の情報登録を面倒に感じ、途中でアプリの利用をやめてしまう可能性
2. 嗜好を反映したコーデ提案ロジックの実装に時間がかかり、卒業制作の期限内に完成させることが難しくなる恐れ
3. 競合アプリ（XZなど）と機能が似ていると評価され、差別化が伝わりにくいリスク

**■ なぜそう思うか：**

1. 既存のクローゼットアプリの多くは入力項目が煩雑で、多くの人が登録作業を負担に感じるという実情がある
2. Railsで高度な推薦アルゴリズムを開発するには工数が大きく、複雑な機能を全部搭載すると開発が間に合わない
3. 外見上は「電子クローゼット＋コーデ提案」という同種のアプリのため、理念の違いを言葉でしっかり説明しないと類似作品と判断されやすい

**■ そのために考えている対策：**

1. MVPの段階でテキストによる簡易登録機能を中心に実装し、必須項目だけに絞って入力負担を最低限に抑える
2. 機能を取捨選択し、高度な画像認識・音声入力などは今回実装せず、将来の拡張機能として割り切る。コア機能に開発リソースを集中
3. 発表時は「ファッションを楽しむツールではなく、意思決定疲労を軽減する生活支援ツール」という根本のコンセプトを最初に強調し、機能だけではなく考えの差を明確に伝える

## 10. 技術スタック

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails 7.0.3.1
- DB：SQLite
- 使用予定ライブラリ：Devise（認証）、Bootstrap（UI）

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
|------|------------|------|
| Ruby on Rails | 採用 | フルスクラッチで開発するよりRailsはCRUD機能を短時間で実装しやすい |
| Django | 不採用 | Pythonも魅力的だが、Railsのenum・ActiveRecord・RSpecを学習する課題のため。実装思想が異なり、既存Rubyのコード資産が流用できない |
| Spring | 不採用 | 機能が過剰で定型コードが多く開発効率が低下。RSpecのテスト資産が利用不可になる |
| MySQL | 不採用 | 今回の規模ならSQLiteで十分。MySQLはサーバー起動・権限設定など追加作業が発生し、開発・テストの手間が増える |
| SQLite | 採用 | 単一ファイル型で環境構築が簡単。MVPは大規模アクセスを想定しないため十分。卒業制作に最適 |
| Bootstrap | 採用 | CSSを一から書く手間を省き、短期間で操作性の良い画面を作成可能。複雑なUIを必要としない |
| React | 不採用 | MVPの機能に高度なフロントエンドは不要。学習コストが増え、技術構成が複雑になるため |

- **今回チャレンジしたい点**：Deviseを使った認証機能、ActiveStorageを使った画像管理、Yahoo!天気APIとの連携
- **不安な点**：
  1. 写真から洋服の種類や色を自動判別する画像認識機能は難易度が高く、Railsのみで高精度に実装することが困難。
  2. ユーザーの評価をもとに嗜好を学習し提案を最適化するロジックの制作に時間がかかりそう。
  3. API連携が初めてなので、ドキュメントを読んで理解できるか少し心配です。
